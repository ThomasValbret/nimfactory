## Réalisé (A.1)

- **`FileBudgetLedger`** : port F0 inchangé (`reserve`, `settle`, `markUnknown`, `releaseBeforeSend`).
- **Validation avant mutation** : `max_microusd` et plafonds de scope non négatifs ; `max_sends` ≥ 0 ; dépassement de plafond rejeté sans mise à jour mémoire.
- **Autorité in-process partagée** : réouvertures sur le même répertoire `*.ledger/` dans un processus → un seul état (compteur de références sur `open` / `close`).
- **Durabilité** : checkpoint `state.json` (écriture `.tmp` + `moveFile`) avec `journal_line_count` ; reprise par **replay** des lignes du journal postérieures au checkpoint ; en absence de snapshot, replay intégral du journal.
- **Rollback transactionnel** : échec de persistance → restauration des tables + troncature du journal à la frontière ; retry idempotent cohérent avec l'état disque.
- **Idempotence** : même `attempt_id` + mêmes paramètres → retour stable ; paramètres différents → `fecValidationFailed`.
- **Nommage** : `fileBudgetLedgerCapabilities()` documente le backend fichier ; `SqliteBudgetLedger` / `openSqliteBudgetLedger` conservés **dépréciés** (ne sont pas SQLite).
- Comportements conservés : `markUnknown` garde la réserve ; comptabilité coût réel / estimated ; tentatives obsolètes comptabilisées.
