## Réalisé

### Backend
- **SQLite local** via liaison dynamique `libsqlite3.so.0` (FFI minimal dans `sqlite_ffi.nim`).
- Choix documenté : le paquet Nim `db_connector/sqlite` n’est pas présent dans le toolchain ; le module `nimagent/runtime/journal_sql` n’est pas importé pour éviter de lier F3 au SDK journal. Pas de store fichier de repli : SQLite système disponible (`sqlite3` 3.45.1).

### RunStore (`SqliteRunStore`)
Implémente les méthodes port F0 :
- `appendEvent` — événements entrants, dédup `message_id`, refus epoch obsolète (`fecStaleSnapshot`)
- `commitTransition` — état + activations/tentatives + effets externes + **outbox** dans une transaction `BEGIN IMMEDIATE` / `COMMIT` ; **contrôle epoch/propriétaire dans la même transaction** que les écritures
- `recover` — reconstitue état, événements, activations, outbox non acquittée, effets, politique `reinvoke_policy`

#### Sémantique idempotente (`commitTransition`)
- Si `transition_id` est déjà persisté, l’appel **retourne le JSON enregistré** sans vérifier à nouveau l’epoch et **sans** ajouter d’événement, d’état ni de message outbox.
- Sinon, un `epoch` présent dans la transition doit **égaler** l’epoch courant du run (`nf_runs.epoch`) au moment de la transaction ; sinon `fecStaleSnapshot` et **aucune mutation**.
- `activation_id` / `attempt_id` exigent respectivement `activation_state` / `attempt_state` ; absence typée `fecMissingRequiredInput` (pas de crash natif).

#### Outbox non acquittée après interruption
- `publishPending` ne sélectionne que les lignes `pending` (comportement inchangé).
- `recover` expose les messages `pending` **et** `publishing` dans `outbox_pending`.
- **`redistributeUnackedOutbox`** : chemin explicite pour les messages restés en `publishing` sans acquittement — retourne les payloads (même `message_id`), repasse le statut à `pending`, puis `publishPending` peut les remettre à disposition.

### API complémentaire (sémantique port, hors méthodes de base)
| Proc | Rôle |
| --- | --- |
| `claimLease` / `currentEpoch` | bail propriétaire ; bump epoch à la reprise |
| `publishPending` / `acknowledgeOutbox` / `pendingOutbox` | publication outbox puis acquittement durable |
| `redistributeUnackedOutbox` | réarmement des messages `publishing` non acquittés |
| `acceptHandlerDelivery` | livraison handler avec dedup et garde epoch |
| `invocationMayBeRequested` | refuse re-invocation si `invocation_validated` |
| `effectOutcomeUnknown` | préserve `effect_outcome_unknown` après recover |
| `CommitCrashPoint` | hooks de test (avant/après commit, après ack) |

`ArtifactRef` : chaînes opaques uniquement (test d’usage distinct sans F1).

```nim
  "transition_id": "tx-1",
  "activation_id": "act-1",
  "attempt_id": "try-1",
  "epoch": 1,
  "invocation_validated": false,
  "state": {"phase": "running"},
  "activation_state": {"status": "running"},
  "attempt_state": {"status": "running"},
  "outbox": [%*{"message_id": "m1", "payload": {"ref": "art-1"}}]

discard store.publishPending("run-1")
# ... crash avant ack ...
for msg in store.redistributeUnackedOutbox("run-1"):
  echo msg["message_id"]
let msgs = store.publishPending("run-1")
store.acknowledgeOutbox("run-1", "m1")
```
